## 一、目标与执行方式

将 XLS 中与加、减、乘和选择器有关的已有优化机制适配到 Yosys 的 RTLIL 字级网表，在原有 opt_share 调用位置执行。最终通过相同的 Yosys 位级展开、ABC 标准单元映射和面积统计，比较 CombArea。

迁移工作分成独立任务，按编号顺序推进。按用户最新指令逐项执行，通过当前任务的最小验证后自动进入下一项，完成任务 11 的实际用例对照后汇报。第一阶段的结果及覆盖范围见末尾执行记录和 src/xls_share/README.md。第二阶段依据 2026-11-09 源码审计补齐当前运算范围的缺项。

任务的实施顺序由数据依赖决定：插件接入 → RTLIL 语义适配 → 局部改写 → 多扇出分析 → 共享合法性 → 共享重写 → 面积评价方案 → 选择策略实现 → 实验入口 → 小规模对照。后续任务复用已经完成的内容，不重复搭建环境或重做相同验证。

每项任务区分三类内容：

- 上游机制：有 XLS 或 Yosys 源码对应的规则和算法。
- 接口适配：为 RTLIL 信号、单元参数、输出端口和工具接口编写的实现。
- 研究改动：改变成本模型、候选选择或覆盖范围的行为。单独说明来源和影响，保留与迁移版本的区别。

### 2.2 数学对象和判定

输入是进入共享优化位置的字级网表。一个候选方案由参与运算、输入选择关系、共享后的运算和所有输出连接共同确定。

必须保持的语义：

1. 全部可观察输出的函数和位宽语义。
2. 符号扩展、截断、加减控制以及选择器定义。
3. 运算结果的全部使用关系，包括模块输出和单元其他输出。
4. 组合依赖无环。

最终优化目标是减少映射后的 CombArea。候选生成、合法性判定、收益判断分开实现和报告。位宽合计等启发式数值作为代理代价单独记录。

对于由选择条件传播得到的使用条件，记 U(v) 为节点 v 的结果被需要的条件。沿每条使用边计算其条件后，汇总所有使用位置：

U(v) = OR over users u of [U(u) AND C(v,u)]。

C(v,u) 表示 u 在什么条件下需要 v。两个运算满足 U(p) AND U(q) 恒为 0，才能作为互斥共享候选；之后还需检查运算兼容性和组合依赖。该关系来自 XLS visibility_analysis；RTLIL 输出端口和信号位的处理属于迁移适配。[S4]

本轮先迁移上述已有机制。联合改写多个 MUX、改变共享组搜索算法等扩展，另立后续研究任务。

### 已确认的问题

1. **需要处理。资源共享和逐边特化仍能改变确定输出。** 折叠与提升已有确定性证明，visibility.cc 的 on_edge、exclusive、routing 和 specialize_once 仍使用未建模 X 的二态控制。隐藏 X 的两个乘积原来均输出零，实际共享后最低位变为 X。另一个反例的条件含 Verilog case equality，逐边特化把 8'hAA 错换成 8'h55。两个反例均走正常插件入口。证据为 run/20261110_xls_audit_final/review_hidden_x_share/verified.log 和 review_eqx_specialize/verified.log。根本处理是统一全部使用条件的证明域，只有证明控制有定义才用它缩小需求，未知条件保留保守的用途。

2. **需要处理。扩大合法边集合会丢掉合法的好组。** case_1732 在原版 opt_share 后的字级 RTLIL 逐字节相同。旧枚举 155 组，新枚举 274 组。旧首选十运算组的全部两两关系在新图中仍合法，组本身从候选集合消失。旧最优估计为 −1664.6071，新首选为 −1443.0975，最终面积 2828.4711 → 2947.6733。按位宽与内部 ID 的 first-fit 会因新顶点改变原批次增长路径。该图有 18414 个合法非单例组，最大组为 11 运算。证据为 review_groups_1732。候选研究应从整组合法集合和面积目标设计搜索，不继续增加静态排序例外。

3. **需要在面积对照中单列。等价位级图的输入序列改变 ABC 映射。** 0083 两版共享成员和门图相同。透明捕获保留真实默认命令；固定输入位标签，按节点真值表和父节点签名确认 611 个逻辑门及常量、全部 PI/PO 同构。重放同一默认脚本、同一库和同一节点名称，仅采用两种 PI、PO、节点与引脚序列，复现 378／396 个映射单元和 1037.6223／1100.0392 面积。候选评分时分配的内部 ID、局部模块复制顺序和 ABC 的首次遇见编号能改变该表示。证据为 review_mapping_0083/before_transparent、unified_transparent 和 replay。该结论由 0083 的重放确认。

4. **需要处理。搜索重复构造大量高度重叠的图。** 4961 的三次共享成员、估计和面积相同，评价组数 1202 → 1832，累计组成员 4384 → 8614，单例耗时 9.895 → 20.270 秒，当前 opt_share 占 98%。每组重复正规化 MACC、配对、构造选择器，并分别重建旧图和新图。parallelize_inputs 会展开链中的多个级别，复制分支总量可达 Θ(k²)，area.cc 先遍历这些节点才从输出排除死逻辑。现有日志未分测 SAT、构造和计价三部分。按成员前缀复用需要固定实际控制，routing 依赖后续组员。
